# usage-metrics

Aggregate, anonymous usage counters for household apps. Other services' backends
POST increments keyed `(app, event, day)` to `/ingest`; `/summary` reads them back
per app × event over the last N days; counters older than the retention window
(default 90 days) are deleted, not archived. No content, no user id, no request
bodies are ever stored, and nothing leaves the box.

## Auth — a service token, not SSO

The callers are other services' backends (per the Solaris-Hub BFF model, an app
talks only to its own backend, which forwards increments here), so per ADR 0009
the credential is a **scoped service token**, not Authelia SSO:

- `USAGE_METRICS_TOKEN` is a `type: "secret"` variable — generated by the wizard
  at deploy, injected as an env var, never a literal in this repo or the image.
- `POST /ingest` and `GET /summary` require `Authorization: Bearer <token>`;
  anything else is a `401`. The service refuses to start without the variable
  rather than serve those routes open.
- `GET /healthz` is deliberately **not** gated: ServiceBay's health poller probes
  it from the host and cannot attach a header, and it discloses only whether the
  retention sweep is still running.

The token is surfaced in the install wizard's SAVE-THESE-NOW banner by
`post-deploy.py`; configure the calling backend with it.

## Networking

Isolated netns with an explicit `hostPort` (ADR 0007) — no `hostNetwork`. On-box
callers reach it as `http://host.containers.internal:{{USAGE_METRICS_PORT}}`,
which is why the port is not loopback-bound; `blockLanAccess` on the port
variable closes it on physical interfaces at the host firewall instead, so the
LAN cannot reach it even with a token.

## Data

`{{DATA_DIR}}/usage-metrics` is bind-mounted at `/data`, and
`USAGE_METRICS_DB_PATH` points at `/data/usage-metrics.db` inside it, so counters
survive a redeploy. The template ships no `*.mustache` companion files, so a
deploy writes nothing into that directory and cannot overwrite the database.

Schema version **1** — the version a new template starts at; there is nothing to
migrate from, so there is no `migrations/` chain and no `CHANGELOG.md` yet.
